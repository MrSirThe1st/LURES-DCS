# ADR-001 — Application boundaries and foundation stack

- **Status:** Accepted
- **Date:** 2026-09-03
- **Owners:** LURES-DCS engineering

## Context

The product needs a dedicated management **desktop** application and a dedicated **mobile** loading application sharing one operational backend (Supabase: PostgreSQL, Auth, Realtime, Storage). The system is for use in the **DRC only** and must support **Mandarin, English, and French**.

Management must not be delivered as a browser or web application.

## Decision

| Layer | Choice |
|-------|--------|
| Management | Dedicated **Tauri 2** desktop application (`apps/desktop`) |
| Loading operations | Dedicated mobile application (`apps/mobile`; current starting point: Expo / React Native) |
| Backend | **Supabase** — PostgreSQL, Auth, Realtime, Storage |
| Shared TypeScript libraries | `packages/design-tokens`, `domain`, `api-contracts`, `data-access`, `ui`, `config`, `utils` |

The repository contains both applications plus shared libraries so domain types and tokens stay consistent. That is **repository organization**, not a product requirement that this system “must be a monorepo.”

Not locked by this ADR: state-management library, extra UI kits, deployment architecture, CI/CD.

Auth provider: **Supabase Auth**.  
DB access: **PostgreSQL via Supabase**, versioned SQL migrations, generated DB types, RLS for authorization.

## Application responsibilities

| App | Responsibility |
|-----|----------------|
| `apps/desktop` | Management UI inside a Tauri 2 window; public Supabase credentials only in the UI bundle |
| `apps/mobile` | Loading-floor UI; talks to backend through safe client APIs/sessions; platform-native UX |

## Package responsibilities

| Package | Responsibility |
|---------|----------------|
| `design-tokens` | Single style source of truth (semantic colors, space, radius, type scales) |
| `domain` | Shared domain types/rules; no React; no DB queries |
| `api-contracts` | Shared Zod schemas / DTOs; no DB implementation |
| `data-access` | Supabase helpers/repositories; privileged access stays out of UI bundles |
| `ui` | Reusable **desktop** UI primitives consuming tokens |
| `config` | Shared TS/ESLint/Prettier bases |
| `utils` | Generic helpers only (not a dumping ground) |

## Dependency boundaries

```
apps → shared packages
data-access → domain, api-contracts
api-contracts → domain (types/schemas as needed)
ui → design-tokens (and utils if needed)
domain → (no React, no DB clients)
```

- UI must not own privileged database access
- Desktop UI and mobile clients must not receive service-role credentials
- Prefer use-case-specific data access over speculative generic repositories

## Authentication approach

Supabase Auth with centralized session helpers. Distinguish authentication (who) from authorization (what) from domain rules (is this valid). Enforce authz with RLS and trusted checks — not UI-only conditionals.

TODO: finalize helper module paths and role claim mapping when auth is wired.

## Database approach

- Versioned migrations under `supabase/migrations/`
- Generated types rather than hand-duplicated table types
- No production schema drift outside migrations
- Excel/CSV is import/export only — never primary state

## Validation approach

Zod at external boundaries (forms, APIs, params, env, imports). Shared schemas live in `api-contracts` when genuinely shared.

## Consequences

- Clear product shape: desktop + mobile + shared backend
- Design tokens prevent divergent palettes
- Tauri 2 avoids shipping Chromium for an internal office app

## Alternatives considered

| Alternative | Why not |
|-------------|---------|
| Management web / Next.js / browser dashboard | Not the agreed product; management is a dedicated desktop app |
| Electron | Heavier runtime; Tauri 2 chosen for this internal office client |
| Separate data stores per app | Breaks the single source of truth |
| Client-only Supabase with service role | Unacceptable security model |

## Validation

- `pnpm install`
- `pnpm lint` / `pnpm typecheck` / `pnpm test` / `pnpm build` (as configured)
- Desktop window: `pnpm --filter @lures-dcs/desktop dev` (requires Rust)
